# Next stop

Native Web Components and plain JavaScript, served by GitHub Pages. New implementation prepared with AI assistance; not recovered from Andur's original Uber exercise. No framework, account, paid API, proxy, API key or installed mapping dependency.

## Components

Import `/components/transit/explorer.js` and add `<transit-explorer>`. It defaults to six nearby MBTA bus stops at Harvard Square. Select a preset area or search locally by stop name/ID. “Use my location” requests permission only after a click. No IP geolocation is implemented. Unsupported locations (including Eugene) show an explicit empty state with manual alternatives, never pretend Boston is nearby.

- `transit-stop-card`: independent presentation, no network fetching. Set `.data = { stop: {id,name,lat,lon,distance?}, index, rows, fetchedAt, recorded?, loading?, error?, popup? }`. A row has `{id,route,destination,time,kind,cancelled,arrivalOnly,description}`; `time` and `fetchedAt` are Unix milliseconds. `popup` hides the map-selection action. It emits composed/bubbling `stop-select` with `{id}`. It updates relative time every 30 seconds and clears its interval when disconnected. Data older than two minutes becomes explicitly stale and uses absolute ET clock times, not optimistic countdowns. Missing predictions are not reported as “no service.”
- `transit-stop-map`: set `.data = {stops, cards: Map<stopId,cardData>, selectedId}`. Native Web Mercator tile renderer, fit/zoom controls, keyboard-accessible 44px numbered pins. Greedy collision separation connects shifted pins to actual coordinates. Selecting a marker opens a card; Close/Escape closes it and restores focus. `selectStop(id,focus)` supports list-to-map navigation; emits `stop-select` and `stop-close`. Popup overlays the desktop map; below 620px it follows the map without covering pins. ResizeObserver is disconnected on removal. Current scope is a fitted nearby-stop map, not a full draggable journey planner.
- `transit-explorer`: coordinates feed requests and owns shared selection/view state; cards and map do not fetch transit data. Refresh is manual and locally disabled for 15 seconds after a request. It cancels superseded requests and ignores late callbacks, including geolocation. It aborts pending feed requests on disconnect. Tests inject `.provider = {loadStops(signal), loadArrivals(stops,signal)}` and `.positionRequester(success,error,options)` before connection. A new provider needs to return the normalized stop and arrival models and supply its own branding, official stop URLs and time zone; the first version's card copy/URLs and clock convention are MBTA-specific.

`model.mjs` supplies distance, search, projection, collision placement, timing and API normalization. `mbta.mjs` is the live adapter: stop directory cached in memory for 15 minutes, 15-second request timeout, one batched prediction request for six stops, one-minute backoff after HTTP 429. It checks for truncated responses. No localStorage, analytics, location history or browser credentials. All external labels render as text or HTML-escaped text.

## Data semantics and sources (checked November 25, 2026)

- [MBTA official API schema](https://api-v3.mbta.com/docs/swagger/swagger.json) and [interactive documentation](https://api-v3.mbta.com/docs/swagger/index.html). Direct anonymous HTTPS requests returned HTTP 200 with `Access-Control-Allow-Origin: *`. The initial bus-stop query returned 6,876 stops with no next page. Defaults search up to 1.6km and show the nearest six by haversine distance, not walking distance. Stop descriptions identify station berths that otherwise share a name.
- Predictions include route and trip resources. Bus uncertainty code 300 is a **schedule-based estimate**; 301 is a delayed prediction; values above 301 are suppressed per the schema. Cancelled/skipped stops are marked, NO_DATA and non-revenue trips are excluded, and arrivals with no departure are labeled arrival-only. These are predictions, not guaranteed service. No complete service-alert integration or schedule fallback is claimed.
- [MBTA developers](https://www.mbta.com/developers). Uses the data as an independent example, no agency logos or claim of endorsement. Requests are low-volume and subject to the agency's service limits and data terms.
- [OpenStreetMap tile policy](https://operations.osmfoundation.org/policies/tiles/): only visible tiles requested at `https://tile.openstreetmap.org/{z}/{x}/{y}.png`; normal browser caching/referrer; visible OSM attribution. No prefetch, bulk/offline download, geocoder, or proxy. Map tiles are best-effort; errors preserve pins and the list alternative. Tile provider may need replacing if traffic grows.
- LTD's discovered `https://feed.ltd.org/gtfs-realtime/tripupdate/` returned 404. Its official static archive at `https://feed.ltd.org/TMGTFSRealTimeWebService/GTFS/google_transit.zip` returned 200 without an ACAO header. This does not prove there is no other LTD integration; it means this pass did not establish an appropriate direct-browser live feed. Do not claim Eugene support. TriMet requires an AppID. No accounts were created or keys borrowed from agency sites.

The stop directory is downloaded without user coordinates; nearest-stop matching and text search run locally. MBTA receives public stop IDs for predictions. OSM sees the requested public-stop map area and the browser IP. No precise visitor coordinates are sent by the code; no third-party IP-location service is contacted. Location denied/unavailable/timeout errors provide preset/search alternatives. Browser permission granting was not exercised on the user's actual location.

`recorded.json` contains a real, small normalized snapshot of MBTA responses captured at its stated timestamp. Each card and the explorer display that it is recorded, with absolute historical times and no live countdown. This is an explicit user-selected fallback, never a silently substituted live feed. It has only the recorded stops in its local search directory; choosing a search result or live preset returns to live mode.

Six cards, map/list/popup sync, close, permission denied/unavailable/timeout, outside coverage, failed refresh preserving marked older data, recovery, ignored late feed/geolocation callbacks, recorded labels and reconnection. Run in the in-app browser; passed November 25. Visible map tiles still use OSM.
- Live browser: real Harvard stops/predictions loaded; map pin opened the correct berth card; list showed all six; stop-ID search selected a new origin; recorded mode showed date/time labels. Mobile popup appears below the map. No horizontal document overflow observed at 320 and 390px. At 768px, the actual explorer also had no horizontal overflow. Keyboard list-to-map selection restores focus to the selected pin; Escape closes the card. A resize-related focus loss was fixed and covered by the browser fixture. This is a smoke check, not a full screen-reader or cross-browser audit.
